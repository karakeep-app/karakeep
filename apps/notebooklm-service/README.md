# Внутренний адаптер NotebookLM

Сервис предназначен только для Karakeep. Один процесс Uvicorn, ограниченное число одновременных операций, SQLite-журнал в `/state`. Версия notebooklm-py закреплена в `requirements.txt`; существующая пользовательская установка не обновляется.

## Запуск

1. Создайте отдельное окружение Python 3.12 и установите `requirements.txt`. Для интерактивной авторизации при необходимости установите `notebooklm-py[browser]==0.8.6` в это окружение. Выполните `notebooklm login`, затем `notebooklm auth check --test` в выделенном профиле Google. Не передавайте содержимое auth-файлов в чат или Git.
2. Подготовьте отдельную директорию авторизации для сервиса. Задайте `NOTEBOOKLM_AUTH_DIR` её абсолютным путём. В контейнере она становится `NOTEBOOKLM_HOME=/auth`; структура профилей должна сохраняться. Укажите `NOTEBOOKLM_PROFILE`, если профиль отличается от `default`. Сервис работает с UID/GID 10001:10001: предоставьте этому пользователю доступ только к выделенной директории. Она монтируется с возможностью обновления сессии. Не меняйте владельца общей пользовательской директории с другими профилями.
3. Создайте случайный `SUMMARY_NOTEBOOKLM_TOKEN`, например через `openssl rand -hex 32`. Сохраните его в закрытом env-файле вне Git. Один и тот же токен задаётся web, workers и адаптеру. Не публикуйте порт адаптера и не помещайте сервис за публичным reverse proxy.
4. Из корня репозитория используйте overlay вместе с основным compose: `docker compose -f docker/docker-compose.yml -f docker/docker-compose.notebooklm.yml up -d --build notebooklm`. Оба файла должны разрешать закрытые настройки окружения. Это запускает только адаптер; новый Karakeep-код требуется отдельно собрать/развернуть перед включением pipeline. Production-образ Karakeep release не получает локальные изменения автоматически.
5. Для Karakeep на той же сети укажите `SUMMARY_NOTEBOOKLM_URL=http://notebooklm:8000` и остальные переменные из документации конфигурации. Для разделённых web/workers подключите оба к этой сети. Сначала оставьте `SUMMARY_PROVIDER=legacy` и `SUMMARY_READER_ENABLED=false`; включение производится после полной приёмки изменения.

`NOTEBOOKLM_CONCURRENCY` по умолчанию 1. `SUMMARY_NOTEBOOKLM_TIMEOUT_SEC` ограничивает всю операцию, включая ожидание свободного места. Клиент Karakeep также должен ограничивать ожидание общим бюджетом задачи. Увеличение числа Uvicorn workers не поддерживается: очередь задач привязана к одному event loop.

## Proxy и сетевой доступ

`NOTEBOOKLM_HTTPS_PROXY`, `NOTEBOOKLM_HTTP_PROXY` и `NOTEBOOKLM_NO_PROXY` overlay передаёт процессу как стандартные переменные HTTPX. Это настройки RPC-соединения сервиса с Google; их нужно проверить для используемого транспорта при развёртывании. Настройки CRAWLER_* не наследуются Python-сервисом автоматически. Импорт URL выполняется инфраструктурой Google и не проходит через proxy crawler Karakeep. Статьи импортируются по URL, а извлечённый Karakeep текст используется как резерв. Проверяется исходный URL, но цепочку редиректов и повторное DNS-разрешение на стороне Google адаптер не контролирует. На своём сервере адаптер не загружает сайты и не следует их редиректам.

## Протокол и диагностика

Все HTTP-маршруты требуют `Authorization: Bearer <token>`, включая `GET /health`. Health подтверждает работоспособность HTTP/SQLite, а не действительность Google-сессии. Docker healthcheck использует токен из окружения без вывода его значения. Не включайте access logs с телами запросов и отладочные журналы Google-транспорта.

- `POST /operations`: UUID operation_id, user_id, source_version, source_type (`article` или `youtube`), url, необязательный text, prompt. Возвращает 202 и состояние.
- Повтор с тем же ID и телом возвращает состояние без новой генерации; изменение тела при прежнем ID даёт 409.
- `GET /operations/{UUID}`: status (`pending`, `success`, `failure`), full_text, markdown, error_code, notebook_id. Исходный текст сохраняется до вызова генерации и остаётся доступен для резерва при её сбое.
- Ошибки содержат только категорию, без cookies, ключей или исходных исключений. При проблемах авторизации выполните проверку профиля на сервере.

Для каждой операции создаётся отдельный notebook. После обработки сервис пытается его удалить. Ошибка удаления сохраняет notebook_id; следующий запуск сервиса повторяет очистку. После аварии прерванные операции получают failure/cancelled, сохранённый текст остаётся доступным; новый запуск Karakeep должен использовать новый UUID. При восстановлении удаляются только notebook с точным префиксом и ID операции из локального журнала. Чужие notebook не затрагиваются.

Завершённые записи без оставшегося notebook удаляются через 24 часа при старте или поступлении новых операций. Поэтому после этого срока повторный POST с тем же ID может запустить новую работу; Karakeep не должен повторять завершённые поколения. SQLite содержит текст источников: защищайте volume и резервные копии. Не очищайте `/state` до удаления оставшихся notebook.

Google получает импортируемый материал. При резерве текст передаётся провайдеру Hermes. Использование своего сервера Karakeep не означает локальную работу модели.

## Проверки

Установите `requirements-dev.txt` в отдельное окружение и выполните `python -m pytest -q` из этой директории. Тесты используют фиктивный Google-клиент и не требуют авторизации; они не заменяют живую проверку статьи и YouTube.

При откате выключите SUMMARY_READER_ENABLED и верните SUMMARY_PROVIDER=legacy. Сначала дождитесь завершения операций и очистки notebook, затем остановите адаптер. Не удаляйте оригинальные HTML/asset Karakeep; локальные офлайн-копии на телефоне обновляются отдельно.
