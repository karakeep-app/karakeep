# Саммари источников через NotebookLM и Hermes

Pipeline включается через `SUMMARY_PROVIDER=notebooklm` после установки Python-адаптера из `apps/notebooklm-service`. Для автоматической обработки нужны `INFERENCE_ENABLE_AUTO_SUMMARIZATION=true` и настройка пользователя. Сначала NotebookLM импортирует URL статьи или YouTube и получает запрос на русское Markdown-саммари. При ошибке импорта статьи можно передать извлечённый crawler текст. Запрос заголовка и описания не заменяет импорт полного источника.

Если NotebookLM не создал результат, Hermes используется только при наличии текста статьи или полученного транскрипта. Видео без доступного транскрипта не превращается в выдуманный конспект по названию. В этом случае остаётся оригинальная ссылка. Исходный материал передаётся Google, а при резерве — провайдеру модели за Hermes. Собственный сервер Karakeep управляет обработкой, но эти модели работают во внешних сервисах.

## Отдельный профиль Hermes

Не направляйте тексты источников в общий агентный gateway с terminal/file/browser и другими инструментами. В проверенной установке основной endpoint `http://172.17.0.1:8642/v1` отвечает с Bearer-авторизацией, модель API — `hermes-agent`, модель берётся из выбранного профиля Hermes. У этого основного профиля инструменты включены. Передача `tools: []` в OpenAI-запросе не является подтверждённым способом отключить инструменты агента.

Корневой `docker-compose.yml` использует установленный на хосте Hermes, без отдельного контейнера. Профиль `karakeep-summary` обслуживается существующим gateway на общем порту 8642 через путь `/p/karakeep-summary/v1`. Дополнительный процесс gateway и отдельный порт не нужны.

Создайте профиль штатной командой `hermes profile create karakeep-summary --no-skills --no-alias`. Укажите в его config.yaml нужную модель и следующие настройки:

```yaml
model:
  default: gpt-6.1-sol
  provider: openai-codex
platform_toolsets:
  api_server: []
mcp_servers: {}
memory:
  memory_enabled: false
  user_profile_enabled: false
platforms:
  api_server:
    enabled: true
```

Авторизуйте провайдера для этого профиля и настройте отдельный случайный `API_SERVER_KEY` в его закрытом `.env` вместе с `API_SERVER_ENABLED=true`. Замените пример модели на используемую вашим профилем. Не копируйте настройки мессенджеров, hooks, MCP и shared memory основного агента. Выполните `hermes -p karakeep-summary gateway ensure`: штатный менеджер подключит профиль к работающему gateway. При изменении файлов профиля gateway автоматически перечитывает их; дождитесь завершения rescan. Не запускайте второй gateway через `--force` и не включайте `gateway.standalone`.

Основной gateway должен слушать адрес, доступный из Docker, например `0.0.0.0:8642`. Корневой compose добавляет `host.docker.internal:host-gateway` для доступа к хосту. Доступ к API защищён отдельным ключом профиля; публиковать endpoint через внешний reverse proxy не требуется.

Настройки Karakeep:

```text
SUMMARY_HERMES_URL=http://host.docker.internal:8642/p/karakeep-summary/v1
SUMMARY_HERMES_MODEL=karakeep-summary
SUMMARY_HERMES_CONTEXT_LENGTH=16384
```

`SUMMARY_HERMES_API_KEY` содержит отдельный ключ этого профиля, не ключ основного gateway. Задайте его вне репозитория и не передавайте мобильному клиенту.

Проверка перед включением:

- GET `/v1/models` с Bearer-ключом возвращает ожидаемую модель.
- GET `/v1/toolsets` не содержит включённых toolsets; для профиля не подключены default MCP servers.
- Тестовый запрос через OpenAIInferenceClient Karakeep возвращает непустой текст.

При переходе с отдельного контейнера на профиль хоста проверены запросы из пересозданного `web`: `/v1/models` возвращает `karakeep-summary`, включённых toolsets нет, запрос без ключа получает HTTP 401, а `/v1/chat/completions` возвращает русское саммари. Профиль обслуживается тем же процессом `hermes-gateway.service`, что и основной агент.

Первоначальная совместимость проверена на временном изолированном профиле установленного Hermes без инструментов и с моделью `gpt-6.1-sol`. Рабочий бюджет Karakeep 16384 проверен обработкой полного текста из 65262 символов по частям и итоговым синтезом. Это не автоматическое определение максимального контекста провайдера: при смене модели проверьте её метаданные и настройку бюджета заново. Ошибки промежуточных частей не игнорируются.

## Ошибки и ограничения

Общий бюджет задачи ограничивает импорт, генерацию, повторы и резерв. У каждого сервиса есть дополнительный таймаут. HTTP-повтор к адаптеру использует прежний operation ID; завершённая операция не должна запускаться заново с тем же поколением. Hermes-клиент отключает внутренние SDK retries, чтобы число попыток контролировалось pipeline. В диагностике сохраняются категории ошибок, без исходных сообщений провайдеров, текста и ключей.

При прямом импорте URL Google сам загружает материал и следует редиректам. CRAWLER_* proxy Karakeep на этот этап не действует. Проверяется исходный публичный URL; адаптер не загружает сайты самостоятельно и не следует их редиректам. Сетевые правила crawler продолжают действовать для его собственных запросов.

## Автотеги по конспекту

`SUMMARY_AUTO_TAGS_ENABLED=true` запускает отдельную задачу Hermes после успешной публикации конспекта статьи или YouTube. На karakeep.onceup.win флаг включён в Compose. Используется тот же выделенный профиль без инструментов; глобальный `INFERENCE_ENABLE_AUTO_TAGGING` для тегирования исходной страницы остаётся выключенным. Настройка пользователя «Автотегирование» распространяется и на этот путь: значение false запрещает обработку.

Hermes выбирает 3–5 разных тематических тегов по готовому конспекту, переиспользуя подходящие имена из словаря владельца. Новые имена русские, технические сокращения допускаются. Сравнение учитывает регистр Unicode, разделители и известные эквиваленты вроде ИИ/AI/искусственный интеллект; существующие имена не переименовываются. При curated-словаре разрешены только его теги; в небольшом словаре возможно меньше трёх результатов. Длинный конспект не обрезается молча: если он не помещается в контекст Hermes, фиксируется отдельная ошибка тегов, а саммари остаётся доступным.

Теги сохраняются как обычные теги Karakeep с `attachedBy=ai`. При обновлении заменяются только прежние AI-привязки этой закладки, пользовательские сохраняются. Сбой тегирования не меняет успешный статус и текст саммари. Повторы и устаревшие ответы защищены поколением и хешем конспекта, запись и создание тегов выполняются в одной транзакции. Индекс, правила и webhooks получают обычные события изменения. На сайте видны ожидание/успех/ошибка подбора тегов; список тегов обновляется после завершения. Приложение App Store получает существующую схему тегов и не требует обновления.

JSON и число уникальных тегов проверяются; модель получает максимум одну попытку исправить формат. Временные ошибки вызывают штатные ограниченные повторы очереди, постоянные ошибки авторизации/квоты/формата не запускают бесконечные запросы. Старые закладки массово не обрабатываются: новая публикация или ручное пересоздание саммари запускает новый цикл тегов. Для отката выключите `SUMMARY_AUTO_TAGS_ENABLED` и пересоздайте web; уже сохранённые теги останутся.

## Режим чтения и откат

Новые саммари используют единый шаблон: «Главное за 30 секунд», основные идеи, подробный конспект по темам и практическая польза, если она есть в источнике. Пользовательские инструкции саммари дополняют этот шаблон для обоих генераторов. Важные числа, примеры, ограничения и мнение автора сохраняются; рекламные вставки и повторы исключаются. Числовые маркеры, подтверждённые метаданными ссылок NotebookLM, убираются перед публикацией, поскольку временный notebook удаляется. Реальные Markdown-ссылки, код и фактические числа сохраняются. Готовые прежние саммари автоматически не перегенерируются.

На сайте над содержимым закладки владельцу показывается этап обработки: ожидание очереди, NotebookLM, Hermes, ожидание повтора, успех или отказ. Видны генератор, время результата и безопасные категории ошибок каждого провайдера. Исходный текст, ID notebook, cookies и сообщения исключений этот endpoint не возвращает. Для существующего приложения App Store контракт не меняется: оно получает новый Markdown/HTML с сервера, дополнительных экранов и новой сборки iOS нет.

Кнопки «Создать саммари», «Повторить обработку» и «Пересоздать саммари» ставят задачу в фон. Одновременно активное поколение не дублируется. Ручной запуск разрешён владельцу независимо от переключателя автосаммари. Временные ошибки `provider` и `timeout` после неудачи всего pipeline получают максимум два новых запуска через 1 и 5 минут; время и счётчик сохраняются в БД, задержка — в постоянной очереди. Новый ручной запуск сбрасывает этот бюджет и может заменить ожидающий отложенный повтор. Поздние ответы и старые задачи не изменяют новое поколение.

При `auth` нужно обновить авторизацию соответствующего провайдера на сервере; при `quota` — дождаться восстановления лимита. `no_text` означает отсутствие полноценного текста/транскрипта, `too_large` — превышение лимита размера. Эти ошибки, отмена и изменение источника не получают автоматических повторов. Если очередь недоступна, состояние становится ошибкой, а не бесконечным ожиданием. Повторная генерация не обновляет уже скачанную офлайн-копию телефона: после успеха используйте **Update offline copy**.

`SUMMARY_READER_ENABLED=true` заменяет HTML в `bookmarks.getBookmark(includeContent=true)` только при успешном саммари актуальной версии источника. Перед текстом стоит пометка «ИИ-саммари», в конце — ссылка на оригинал. Markdown преобразуется в HTML с разрешёнными заголовками, списками и таблицами; скрипты, обработчики событий, небезопасные URL, iframe и изображения удаляются.

Подмена не ограничена iPhone: любой клиент этого общего endpoint может получить саммари. `getBookmarkReadableContent`, выдача списков с содержимым и экспорт продолжают читать оригинал. Исходный HTML и contentAssetId не перезаписываются; регенерация не получает предыдущий конспект вместо источника.

До готовности, после ошибки и после изменения источника reader получает оригинал. Старые саммари без записи происхождения не подменяют reader до успешной новой генерации. При повторном запуске прежний Markdown остаётся сохранённым в AI Summary, но во время ожидания/ошибки reader показывает оригинал. Индекс и уведомления обновляются после атомарной публикации нового результата.

Автоматическое сохранение ссылки запускает очередь, если разрешены автосаммари. Ручная регенерация использует те же генераторы и возвращает прежний ответ `{summary}`; долгий запуск может вернуть TIMEOUT после SUMMARY_MANUAL_WAIT_SEC, продолжая обработку на сервере. В таком случае позже запросите закладку повторно. Сервер не обещает мгновенно обновить уже открытый экран мобильного приложения.

Проверяйте переключатель с установленным приложением App Store. В протокол приёмки внесите версию/build приложения и сервера, отправку статьи/видео через Share, вид до и после генерации, необходимое действие обновления, заголовки и списки, исходную ссылку и поведение выделений/позиции чтения. На karakeep.onceup.win подмена включена по запросу владельца для этой проверки; совместимость App Store пока не подтверждена. Описание Compose и подключения находится в `docker/README.onceup.md` репозитория.

Офлайн-копия, скачанная до генерации, продолжает содержать оригинал. После готовности саммари её нужно обновить доступным в вашей версии приложения способом; затем проверить чтение без сети. Сервер не может принудительно заменить локальный кеш отключённого iPhone. Сохранённые позиции и выделения оригинала могут не соответствовать тексту конспекта; автоматический перенос не выполняется.

Для отката выключите `SUMMARY_READER_ENABLED` и перезапустите web/workers с одинаковыми настройками. Следующий серверный запрос снова вернёт оригинал; старые офлайн-копии обновляются отдельно. Чтобы отключить новый генератор, верните `SUMMARY_PROVIDER=legacy`. Аддитивную таблицу состояния и сохранённые источники удалять не требуется; массовая перегенерация существующей библиотеки не запускается автоматически.
