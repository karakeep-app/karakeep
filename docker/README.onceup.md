# Karakeep на karakeep.onceup.win

Рабочий Compose находится в корне репозитория: `docker-compose.yml`. Он собирает текущий код с саммари, запускает web и workers в одном контейнере, Meilisearch, Chrome и NotebookLM-адаптер. Резерв использует отдельный профиль существующего Hermes gateway на хосте. Публикуется только Karakeep через существующий Traefik в сети `proxy`; порты контейнеров не привязаны к хосту. Сеть, entrypoints `http`/`https`, middleware `traefik-https-redirect`/`sslheader` и resolver `cloudflare` соответствуют установке `/apps/snaplex`.

## Текущее подключение

- Адрес: https://karakeep.onceup.win.
- В браузере: кнопка Pocket ID, вход существующей учётной записью с passkey.
- Первая учётная запись уже создана через Pocket ID и получила роль администратора. Регистрация и вход по паролю отключены.
- На iPhone: в приложении Karakeep указать этот адрес, выбрать **Use an API key instead** и вставить ключ из закрытого файла `/apps/karakeep/.deploy/iphone-api-key.txt`. Ключ относится к той же учётной записи. Можно создать другой ключ в веб-интерфейсе, в настройках API Keys, и отозвать прежний.

Просмотренные мобильные исходники поддерживают пароль и API key; прямого входа через OIDC в них нет. Pocket ID используется для входа в браузере и управления учётной записью, API key — для существующего мобильного клиента. Перед приложением не установлен отдельный экран авторизации reverse proxy.

Автосаммари включены: NotebookLM импортирует URL статьи или YouTube первым. Hermes вызывается автоматически при сбое, если уже доступен полный текст или транскрипт. Подмена reader включена по запросу владельца для проверки на его iPhone. Совместимость конкретной версии App Store и её офлайн-кеша ещё требует проверки на устройстве.

## Файлы и секреты

`.env` содержит уникальные ключи и OIDC client secret. `.deploy/` содержит Google storage state, состояние адаптера и мобильный API key. Каталог имеет права `700`, секретные файлы — `600`. Оба пути исключены из Git и Docker build context.

NotebookLM использует `.deploy/notebooklm-auth/profiles/default/storage_state.json`; постоянный журнал операций расположен в `.deploy/notebooklm-state/`. Google-авторизация скопирована из уже авторизованного профиля владельца. После истечения сессии нужно обновить авторизацию штатным `notebooklm login`, заменить storage state и перезапустить адаптер. Веб-страницы авторизации с сервера публично не открываются.

Hermes использует профиль `/home/onceup/.hermes/profiles/karakeep-summary` существующего gateway и маршрут `http://host.docker.internal:8642/p/karakeep-summary/v1`. Compose добавляет `host.docker.internal:host-gateway`. API alias — `karakeep-summary`, модель профиля — `gpt-6.1-sol`. `platform_toolsets.api_server: []`, `mcp_servers: {}`, память отключена; инструменты не доступны запросам саммари. Используется отдельный ключ профиля из `.env`. Доступность модели и отсутствие включённых инструментов проверены запросами из web-контейнера. Этот gateway управляется отдельно от Compose; его профиль и авторизацию нужно резервировать отдельно. Остановка Hermes не блокирует запуск Karakeep и NotebookLM, но резервный генератор становится недоступен.

## Автотеги

`SUMMARY_AUTO_TAGS_ENABLED=true` включает 3–5 AI-тегов через выделенный Hermes после готовности конспекта. Настройка пользователя может отключить автотеги. Существующие теги переиспользуются, ручные привязки сохраняются; `AI`, `ИИ` и «искусственный интеллект» не создают новые дубли. Ошибка тегирования не отменяет саммари. На сайте показывается отдельный статус подбора тегов; iPhone получает стандартные теги без обновления приложения. Прежние саммари и теги массово не меняются: для нового цикла используйте «Пересоздать саммари». Отключение флага не удаляет сохранённые теги.

## Повторный запуск и обновление

Из `/apps/karakeep`:

```sh
docker compose config --quiet
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 web notebooklm
curl -fsS https://karakeep.onceup.win/api/health
```

Сборка из этого дерева обязательна: стандартный upstream-образ не содержит новый pipeline и миграцию `0097_summary_processing`. Миграции применяются при старте web. База и assets находятся в постоянном томе `karakeep_data`, индекс поиска — в `karakeep_search`. Не использовать `docker compose down -v` для обычного обновления.

Для новой установки взять `.env.compose.example`, заменить все placeholders и создать каталоги авторизации с владельцем `DEPLOY_UID:DEPLOY_GID`. Сгенерировать каждый секрет отдельно, например `openssl rand -hex 32`. Создать confidential OIDC client в Pocket ID с callback **`https://karakeep.onceup.win/api/auth/callback/custom`**, PKCE и launch URL `https://karakeep.onceup.win`. Записать client ID/secret в `.env`. Для первого входа на пустой БД временно разрешить регистрацию (`DISABLE_SIGNUPS=false`), ограничив доступ к клиенту в Pocket ID владельцем; первый пользователь Karakeep становится администратором. После входа вернуть `DISABLE_SIGNUPS=true` и пересоздать web. На текущей установке этот шаг уже выполнен; повторять его не нужно.

## Резервная копия

Сохранять согласованную копию БД вместе с assets и секретами. Например, при короткой остановке сервисов:

```sh
mkdir -p .deploy/backups
chmod 700 .deploy/backups
docker compose stop
docker run --rm -v karakeep_data:/data:ro -v "$PWD/.deploy/backups:/backup" alpine tar czf /backup/karakeep-data.tar.gz -C /data .
tar czf .deploy/backups/karakeep-config.tar.gz .env .deploy/notebooklm-auth .deploy/notebooklm-state
chmod 600 .deploy/backups/*.tar.gz
docker compose up -d
```

Хранить копию за пределами сервера в закрытом хранилище. Профиль Hermes и его авторизация сохраняются отдельно средствами резервирования host gateway. Индекс Meilisearch можно восстановить штатной переиндексацией Karakeep. Для восстановления остановить стек, вернуть содержимое data-тома и приватные каталоги с исходными правами, затем запустить ту же версию кода. Авторизации внешних провайдеров при необходимости обновить отдельно.

## Проверка iPhone и откат reader

После входа отправить статью и публичное видео с субтитрами через Share → Karakeep. До готовности доступен оригинал. После генерации закрыть и повторно открыть закладку с получением свежих данных; проверить русский текст, заголовки, списки и ссылку «Открыть оригинал». Затем обновить офлайн-копию способом, доступным в установленной версии приложения, и проверить без сети. Записать версию/build приложения и наблюдаемое поведение. Старую офлайн-копию сервер сам не заменяет, позиция и выделения оригинала автоматически на саммари не переносятся.

Чтобы вернуть оригинал в reader, установить `SUMMARY_READER_ENABLED=false` в `.env` и выполнить `docker compose up -d web`. Сохранённые исходники и саммари остаются в БД. Скачанные копии на телефоне обновляются отдельно.
