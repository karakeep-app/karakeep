# Proposal

## Why

Пользователь сохраняет статьи и YouTube с iPhone и хочет читать структурированный ИИ-конспект в существующем приложении Karakeep из App Store. Отдельный блок AI Summary неудобен: результат должен занимать основной режим чтения, при сохранении исходного материала.

## What Changes

- Добавить серверную генерацию саммари через notebooklm-py с автоматическим резервом через установленный Hermes API gateway.
- Использовать полный текст статьи или транскрипт; не выдавать саммари метаданных за саммари видео.
- Включаемая серверная настройка заменяет выдаваемый HTML режима чтения безопасным HTML саммари, сохраняя оригинал и исходный URL.
- Пока результата нет или обработка не удалась, выдавать исходный материал; для YouTube без текста сохранять доступ к видео.
- Проверить реальное приложение App Store, повторное открытие и офлайн-кеш; обновление мобильного приложения не является предпосылкой реализации.
- По последующему запросу владельца развернуть текущую сборку на karakeep.onceup.win через Docker Compose и существующий Traefik; использовать Pocket ID в браузере и API key той же учётной записи на iPhone. Включить reader для проверки владельцем, сохранив незавершённую приёмку App Store отдельно.
- По запросу владельца улучшить общий шаблон конспекта и очистку недоступных ссылок NotebookLM; добавить на сайт этапы генерации, безопасные ошибки провайдеров, фоновый ручной повтор и ограниченные отложенные повторы временных ошибок. Код и сборка приложения App Store не изменяются.
- После готовности конспекта добавлять через Hermes 3–5 тематических тегов, переиспользовать словарь владельца и избегать дублей; сохранять обычные AI-теги Karakeep без изменения приложения.

## Capabilities

### New Capabilities

- `source-summarization`: обработка статей и YouTube, NotebookLM первым, Hermes при наличии исходного текста, устойчивость фоновых задач.
- `summary-reader-content`: совместимая выдача саммари в режиме чтения с сохранением оригинала и проверкой кеширования.

### Modified Capabilities

Нет: существующих спецификаций OpenSpec пока нет.

## Impact

Затрагиваются workers/inference, получение исходного текста, настройки сервера, хранение происхождения результата и выдача tRPC bookmarks.getBookmark. Нужно согласовать ручную регенерацию с фоновой генерацией. Новый Python-компонент notebooklm-py требует Google-авторизации и отправляет материалы Google; Hermes требует проверки действующего endpoint и модели. Совместимость текущих мобильных исходников не доказывает совместимость установленной App Store версии. Другие клиенты общего API могут также видеть саммари при включённом режиме; исходные экспорт, индексация и обработка должны читать оригинал. Новая сборка iOS, аудиотранскрипция видео без доступного текста и визуальный анализ видео не входят в объём.
