## Оставшаяся приёмка

Задачи 6.2 и 6.3 остаются открытыми. Владелец сообщил версию App Store 1.13.0 и появление саммари онлайн для своего YouTube. Номер build, полная проверка статьи, форматирования, обновления и исходной ссылки пока не зафиксированы. Прямого доступа к устройству нет; проверки исходников и API не заменяют приёмку.

При проверке без сети владелец предоставил скриншот: авиарежим включён, открыта закладка «Product, podcasts, and…», показано «You're offline / This page isn't available while you're offline. Reconnect to load it». Владелец отдельно подтвердил, что был открыт режим чтения. Офлайн-проверка в этом сценарии не прошла; считать поддержку подтверждённой нельзя. Пока неизвестно, выполнялись ли Make available offline / Update offline copy и появилось ли подтверждение успешного сохранения перед отключением сети. Нужен повтор с явно скачанной актуальной копией. В просмотренных исходниках reader отдельно читает offlineLibrary, а ручное сохранение запрашивает getBookmark(includeContent=true) и показывает Available offline / Offline copy updated; простое открытие онлайн не равнозначно этому действию.

Результат повторной проверки: владелец сообщил, что после ручного нажатия **Make available offline** чтение сработало без сети на версии 1.13.0. Таким образом, ручное сохранение саммари и последующее офлайн-чтение для этой закладки подтверждены пользователем. Первоначальное сообщение об ошибке не воспроизвелось после явного скачивания копии. Отдельно остаются непроверенными автоматические загрузки, замена старой офлайн-копии оригинала после генерации, форматирование без сети, выделения и позиция чтения; задача 6.3 до полной проверки остаётся открытой.

SUMMARY_PROVIDER=notebooklm и SUMMARY_READER_ENABLED=true включены по запросу владельца для использования и проверки на его iPhone. Совместимость конкретного мобильного клиента пока не заявлена. Изменение не архивируется до завершения приёмки.

## Развёртывание karakeep.onceup.win

Корневой `docker-compose.yml` собрал локальный AIO-образ и запустил web/workers, Meilisearch, Chrome и NotebookLM-адаптер. Публикация через существующий Traefik, сеть proxy, HTTPS resolver cloudflare. Все сервисы работают; web, search и notebooklm проходят healthcheck. Прямых host ports у контейнеров нет. Данные сохраняются в постоянных томах и закрытом `.deploy/`.

В существующем Pocket ID создан confidential OIDC client с PKCE и точным callback `/api/auth/callback/custom`. Полный вход, создание первого администратора и повторный вход после отключения регистрации проверены. Публичная страница входа содержит Pocket ID; email signup/signin возвращают 403. Мобильный API key относится к той же учётной записи, хранится только в закрытом локальном файле. Через публичный HTTPS проверены `/api/v1/users/me` и `apiKeys.validate`, используемый просмотренными мобильными исходниками.

При проверке обнаружен реальный дефект: локальное файловое хранилище отвергало `text/plain` при сохранении исходника саммари. Тип добавлен только в поддерживаемое внутреннее хранилище, без разрешения пользовательской загрузки этого типа. Новая регрессия с настоящим LocalFileSystemAssetStore проверяет запись и чтение русского текста. Обновлённый образ пересобран и опубликован.

Повторная серверная проверка сохранённых через публичный API ссылок:

| Источник | Генератор | Саммари | Reader и исходник |
| --- | --- | --- | --- |
| Wikipedia: Spaced repetition | NotebookLM | 5508 символов | tRPC getBookmark: ИИ-саммари, заголовки, списки, reader_view; URL сохранён, readable content отдаёт оригинал |
| YouTube: arj7oStGLkU | NotebookLM | 5974 символа | tRPC getBookmark: ИИ-саммари, заголовки, списки, reader_view; URL сохранён, readable content отдаёт оригинал |

Проверены pending до публикации с исходным содержимым, success с provenance notebooklm и сохранённый source asset для обоих материалов. Тестовые ссылки оставлены в библиотеке для проверки владельцем на устройстве.

Во время работы Compose параллельно переключён на профиль `karakeep-summary` существующего Hermes gateway. Итоговый маршрут `http://host.docker.internal:8642/p/karakeep-summary/v1`, alias `karakeep-summary`, модель `gpt-6.1-sol`. После переключения из web-контейнера проверены `/models`, отсутствие включённых инструментов в `/toolsets` и настоящий непустой ответ `/chat/completions`. Отдельный временный контейнер Hermes больше не используется. Контролируемый fallback полного текста был проверен ранее, как описано выше.

После исправления: shared 154 и shared-server 58 тестов passed; отдельный файловый provider — 2 теста passed. Typecheck, lint и format для shared/shared-server/plugins прошли. Compose config, HTTPS health и git diff --check прошли. Документация запуска, входа с iPhone, секретов, резервного копирования и отката: `docker/README.onceup.md`; несекретный шаблон: `.env.compose.example`.

## Новый формат и восстановление обработки

По запросу владельца доработаны только сервер и сайт. `apps/mobile` не менялся, новая сборка App Store не требуется. Добавлена аддитивная миграция `0098_summary_progress`: этап, безопасные ошибки NotebookLM/Hermes, счётчик отложенных повторов и время следующего запуска. Перед обновлением сохранена согласованная резервная копия базы; прежний AIO и адаптер сохранены под локальным тегом `pre-summary-progress`.

Шаблон общий для двух генераторов: «Главное за 30 секунд», основные идеи, подробный конспект с тематическими подразделами и практическая польза при наличии в источнике. Python-адаптер очищает числовые ссылки, подтверждённые метаданными цитирования NotebookLM, сохраняя ссылки Markdown, код и фактические числа. Прежние саммари массово не меняются.

На опубликованном сервере создана тестовая статья Wikipedia Active recall — «Проверка нового формата саммари». Настоящий NotebookLM успешно обработал полный текст в 148292 символа; затем выполнена повторная генерация кнопкой сайта. Результат второго запуска — 8437 символов с четырьмя разделами шаблона и тематическими подразделами, без числовых маркеров ссылок. Reader endpoint отдаёт HTML саммари, readable export сохраняет оригинал. Ранее сохранённые тестовые закладки уже отсутствовали в базе до этого обновления, что подтверждено предмиграционной резервной копией; для проверки использована новая закладка, данные не восстанавливались и не очищались.

Проверка интерфейса Playwright на опубликованном сайте:

- Настоящая кнопка «Пересоздать саммари» ставит задачу в фон; наблюдались queued/notebooklm/success, видны генератор и время результата.
- На тестовых ответах API проверены понятная ошибка auth с доступной кнопкой повтора и retry_wait со счётчиком и временем следующего запуска. Учётные данные провайдеров и реальные результаты для этой проверки не изменялись.
- Отдельная проверка перехода pending → success подтвердила обновление тела reader без перезагрузки страницы (повторное получение content-bearing ответа).
- Ошибок JavaScript не обнаружено. Снимки и несекретные результаты проверок сохранены в закрытом `.deploy/`.

Серверные проверки: manual retry защищён владением, областью API key, ограничением частоты и проверкой активного поколения. Два постоянных задания через 60 и 300 секунд используют новые поколения; поздние задачи не публикуются, ручной запуск сбрасывает бюджет и может заменить ожидающий повтор. Auth/quota/no_text/too_large/cancelled/source_changed не запускают автоматический цикл. Временный отказ NotebookLM до получения YouTube-транскрипта сохраняет исходную категорию provider/timeout и получает ограниченный повтор, без вызова Hermes по метаданным.

Итоговые проверки: shared — 154, shared-server — 77, trpc — 560 тестов passed; Python — 32 passed. Проверены миграция существующего саммари, сохранность оригинала и публикации, защита от дубликатов и гонок, безопасная выдача и запрет запуска с read-only API key. Typecheck всех шести затронутых пакетов и форматирование пройдены; lint проходит с 19 существующими предупреждениями React в web, без новых ошибок. Все 29 новых строк переведены на 34 локали, ключи и placeholders проверены; прочие прежние пропуски переводов не менялись.

Офлайн-копии iPhone после повторной генерации обновляются вручную через **Update offline copy** или средствами автоматической загрузки клиента. Задачи 6.2/6.3 остаются открытыми в ранее указанной части; дополнительные экраны диагностики реализованы только на сайте.

## Автотеги после готовности конспекта

Добавлена миграция `0099_summary_tags` с отдельными полями состояния/ошибки тегирования и хешем обработанного конспекта. До обновления сохранена резервная копия базы и образ `pre-summary-tags`. В Compose включён `SUMMARY_AUTO_TAGS_ENABLED=true`; прежнее тегирование исходной страницы остаётся выключенным. Публичная настройка доступности автотегов учитывает новый путь, пользовательское отключение autoTaggingEnabled=false проверяется до запроса и перед записью.

После успешной публикации конспекта в постоянную очередь ставится отдельная задача summary_tags. Используется тот же выделенный Hermes с отключёнными инструментами и отдельным ключом; глобальный inference client не требуется. Генератор получает полный готовый конспект и ограниченный по контексту словарь только владельца. Проверены 3–5 уникальных результатов, русский язык новых имён с допустимыми техническими сокращениями, существующие имена и curated-ограничения. Формат JSON допускает одну попытку исправления; огромный конспект не обрезается молча.

Запись тегов проверяет поколение, хеш и источник в транзакции с резервированием записи. Сохраняются ручные привязки, заменяются только AI-привязки, события передаются индексу, правилам и webhooks. Проверены известные эквиваленты AI/ИИ/искусственный интеллект, Unicode-регистр и разделители; совпадение произвольных синонимов не объявляется универсальной гарантией. Ошибка тегирования не меняет успешный результат саммари, поздняя ошибка дубликата не отменяет уже завершённое тегирование.

Живая проверка на karakeep.onceup.win: у тестовой статьи Active recall повторно создан конспект NotebookLM из 8750 символов. Пока Hermes подбирал теги, reader уже отдавал саммари. Затем через обычный API получены пять тегов с attachedBy=ai:

- когнитивная психология;
- интервальное повторение;
- активное воспроизведение;
- долговременная память;
- методы обучения.

В базе taggingStatus=success, taggingErrorCode=null, taggedSummaryHash совпадает с хешем конспекта. Playwright подтвердил статус «Tags updated», пять AI-плашек и сохранение саммари в reader. Снимок `.deploy/auto-tags-ready.png` и несекретный протокол `.deploy/auto-tags-live-result.json` сохранены приватно. Ключ существующего приложения iPhone по-прежнему проходит apiKeys.validate; `apps/mobile` не менялся.

Проверки после доработки: shared — 155, shared-server — 96, trpc — 560 тестов passed (811 суммарно). Включены миграция с 0098 с сохранением тегов/оригинала, изоляция владельцев, сохранение ручных тегов, curated-словарь, Unicode/AI-дубли, некорректный JSON, чрезмерный контекст, повтор очереди, изменение конспекта/поколения/настроек во время запроса, удалённый тег и запоздалая ошибка дубликата. Typecheck, lint и format шести затронутых пакетов пройдены; прежние 19 предупреждений React в web сохранены. Четыре новых подписи переведены на все 34 локали. Проверены сборка AIO, миграция в работающем стеке, HTTPS health, Compose config, git diff --check и строгая валидация OpenSpec.

Автотеги применяются к новым публикациям конспектов. Для старого результата нужен новый цикл через «Пересоздать саммари»; массовая обработка прежней библиотеки не запускалась. Получение новых тегов на телефоне использует обычное обновление данных закладки; новую App Store сборку устанавливать не нужно.
