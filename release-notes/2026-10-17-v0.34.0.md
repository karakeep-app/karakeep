# 0.34.0

Welcome to the `0.34.0` release of Karakeep (and sorry for the long wait)! The mobile app gets most of the attention this time: **Automatic offline downloads** for recent bookmarks and particular lists, **tablet layouts**, tag management, public lists, collaborators and attachments, all of which used to need the web app. The crawler got a big anti-bot overhaul: it now drives real **Google Chrome through patchright**, so far fewer sites will hand you a "Just a moment..." page instead of the article. There are also a lot of memory and performance improvements, along with tons of bug fixes.

Thanks to everyone who contributed to this release: @justadityaraj, @InventorB, @ryanchou1994, @NoiceHax, @0-0mfuji, @eriktews, @qwist1233-cpu, @lightsabit, @BrownieCoder, @itz-puneet, @jreiml, @deepcfr, @mislav, @pradeepb28, @Kyzcreig, @gowinder, @samuel-sarmah, and everyone who triaged bugs or shared feedback.

*Note: the changes mentioned here for the extension and mobile releases will need to go through the different store (apple, google, mozilla) reviews. So it might take a couple of days until all of them are released.*

# New Features 🚀

* **Karakeep's auth moved from next-auth to better-auth**:
  * This is an infrastructure change, but it's a big one. Karakeep moved its auth library to better-auth (away from next-auth). This will unlock a lot of new features in the future (e.g. 2fac, oauth login in the mobile app, hosted MCP auth, etc).
  * This migration is going to happen automatically after the upgrade BUT there are some caveats, please read the "Upgrading" section.
* **Automatic Offline Downloads**: 0.33 let you save single bookmarks for offline reading on the mobile app. In this release, you can let karakeep automatically download recent bookmarks for you while the app is open, and also mark specific lists to be always fully available offline.
* **Mobile app catching up with the web**:
  * Tablet layout showing multiple columns on wide screens.
  * Tag management: rename and delete tags from the app (fc401d02).
  * Manage public lists and list collaborators (292c13a5).
  * View and download bookmark attachments (27774f97).
  * A new usage statistics screen (6563ee14).
  * Pick a parent list, choose a list icon, and create lists straight from the "Manage Lists" page (7ca5ee23, 428d1f22, f9777128).
* **A crawler that gets blocked less**:
  * The crawler now drives the browser with [patchright](https://github.com/Kaliiiiiiiiii-Vinyzu/patchright), a Playwright fork that doesn't leak the automation signals that bot-protection scripts look for (af8b0eb0).
  * The `karakeep-chrome` image now ships Google Chrome stable instead of Chrome Headless Shell, as protected sites block the headless shell far more often (ea57af18). This comes at the cost of the chrome image getting bigger unfortunatly.
  * The user agent now comes from the actual browser instead of a hardcoded Chrome 124 one (254174ac).
  * Cloudflare's "Just a moment..." and DataDome's device check clear on their own after a few seconds. The crawler now waits for them (up to `CRAWLER_CHALLENGE_WAIT_SEC`, default 15s) instead of saving the challenge page (18003460).
  * New `CRAWLER_BROWSER_TIMEZONE` to make the browser's timezone match your proxy's location, as a UTC browser behind a non-UTC proxy is a strong bot signal (ba8c1885).
* **On-demand video preservation** (#3183): A new "Preserve Video" bookmark action downloads a single bookmark's video with yt-dlp. You can now keep automatic video downloads off and still preserve the ones you care about.
* **Broken links management revamp** (#3105): The broken links settings page now groups issues by category and supports search, sorting, retrying and bulk deletion.
* **Search**: New `has:notes` and `has:highlights` qualifiers by @BrownieCoder (#3053).
* **Others**:
  * New `CRAWLER_FULL_PAGE_ARCHIVE_MAX_SIZE_MB` to discard full-page archives above a certain size (media-heavy pages can produce 1GB+ archives that never render) by @NoiceHax (#3054).
  * Pages uploaded as precrawled archives (e.g. SingleFile uploads, and client-side crawling) now get a screenshot too (#3161).
  * Banner images are now resized and converted to WebP to save storage (#3165).
  * The default tagging model is now `gpt-6-luna` which costs half as much as `gpt-5.6-luna` used to cost (thanks OpenAI?).

# Fixes 🐛

* **Performance and memory**:
  * Fix a server memory leak caused by the query cache (#3138).
  * Workers and web only load the dependencies of features that are enabled cutting memory usage for most setups. You should expect a 40MB drop in RSS with this release.
  * Prometheus default metrics are no longer collected when Prometheus isn't configured (#2397). This fixes a regerssion introduced in 0.29 and should result into a lower baseline CPU usage.
  * Faster tag searches by @0-0mfuji (#3089).
  * Search indexing now defaults to 50 workers (instead of 1) for better batching. Should result in faster indexing for large imports.
  * SQLite now runs `PRAGMA optimize` on open and daily (355a0b09).
  * Faster lists page and list stats queries and a smaller main web bundle (2d7cc4bd, 44ea0284, b640f15b).
* **Hardening**:
  * Upload body size is now enforced before parsing the multipart body (3e22b659).
  * Asset downloads now respect client backpressure instead of buffering in memory (b5cab5be).
  * Pagination limits are now validated on all tRPC endpoints (94e1ea21).
  * Content length is capped before tokenizing AI prompts (ef07e913).
  * Upgraded Next.js to 16.4.1 for its October security release (#3196).
* Collaborators' bookmarks now show up in public lists by @NoiceHax (#3019).
* Moving a list under one of its own sublists is now rejected, as the resulting cycle could send list deletion into an infinite loop. Reported by @Vertextheonesolution (GHSA-892w-x93w-2fqp, #3199).
* Fix bookmark pagination tie breakers that could skip or duplicate bookmarks (135f1163).
* Fix the headers timeout for AI inference jobs with slow providers by @eriktews (#2888).
* Fix embedding generation with providers that don't default to float embeddings (#3009).
* Bookmarks deleted while being indexed no longer dangle in meilisearch (bca289d2).
* The RSS fetcher now identifies itself with a karakeep specific user agent (adf399be).
* If one of the workers fails, the whole worker process now crashes instead of silently running without it, so your container's restart policy can kick in (ae9e23b3).
* Fix `.jpg` uploads being rejected in the attachment box (2434e657).
* Fix the header shrinking in Safari (3c441143).
* Fix duplicate "sort by" in the all tags page (f5e56b42).
* Fix the sidebar's "+" (new list) button messing up the bookmark preview modal when clicked while a bookmark is open by @samuel-sarmah (#3192).
* Make `/run` owned by `node` in the docker image so non-root setups work by @lightsabit (#3114).
* Mobile:
  * Fix lost and duplicated Android shares after the app gets killed (e7fbaab7). This has been a long standing problem, and should signficantly improve share reliability for android.
  * Ignore Android's unreliable internet reachability checks that marked the app offline (#3127).
  * Fix the server save button getting hidden by the keyboard by @InventorB (#3010).
  * Markdown list bullets and numbers now use the foreground color by @ryanchou1994 (#3046).
  * Fix lists not getting auto refreshed when a bookmark is added to it (f4efff99) and vertical images in bookmark info (482369b7).
  * Fix a bug that was causing mobile API keys to not be revoked on mobile app logout (1820693e).
* Added missing Turkish translations by @qwist1233-cpu (#3111).

# Upgrading 📦

**Things to know before upgrading:**
* **Everyone gets signed out once.** The move to better-auth (#3140) switches web sessions from JWTs to database sessions, so all web users will need to sign in again. Mobile apps and API keys are not affected.
* **Auth env changes**:
  * This release will automatically lowercase all email stored in the database (in prep for making email case insensitive), except accounts that will cause a conflict (two accounts that differ only in email case). You *Must* fix those conflicts before upgrading (by deleting the unused one). You'll get locked out if you have two conflicting accounts (neither of which are lowercase). If you get locked out, change the email address in the sqlite database to be lowercase to gain access back.
  * New `AUTH_TRUSTED_ORIGINS` (default `*`) to restrict which origins can sign in and be redirected to on top of `NEXTAUTH_URL`.
  * `NEXTAUTH_URL` and `NEXTAUTH_SECRET` keep their names and are still required.
* **Migrate to the `karakeep-chrome` image if you haven't already.** Check the migration guide [here](https://docs.karakeep.app/administration/chrome-image-migration). Browserless (mostly unraid users) will continue to work but will miss out on the stealth improvements. It's advised to migrate to karakeep-chrome's unraid template maintained by @Collectathon.

To upgrade:
* If you're using KARAKEEP_VERSION=release, run `docker compose pull && docker compose up -d`.
* If you're pinning it to a specific version, upgrade the version and then run `docker compose pull && docker compose up -d`.
